# Rick and Morty

Застосунок з двома екранами: 
1) Список персонажів із пагінацією 
2) Екран деталей

SwiftUI + TCA, офлайн режим з Realm, кешування зображень через Nuke.

**Вимоги:** iOS 17.0+, Xcode 26

---

## Як запустити

```bash
git clone https://github.com/AntonBindovskyi/RickAndMorty
cd RickAndMorty
open RickAndMorty.xcodeproj
```

Далі:
Xcode підтягне пакети автоматично при першому відкритті.
Перша збірка може тривати декілька хвилин. Наступні збірки швидкі.

Ключів, конфігураційних файлів, CocoaPods чи інших ручних кроків не потрібно.

### Для перевірки офлайн-режиму

1. Запустити застосунок, прокрутити 2–3 сторінки списку.
2. Закрити застосунок повністю (викинути з памʼяті).
3. Вимкнути Wi-Fi на Mac — симулятор використовує мережу хоста.
4. Запустити знову.

Застосунок запуститься з даними які були завантажені в попередній раз.

## Структура проєкту

```
RickAndMorty/
├── RickAndMorty.xcodeproj
├── RickAndMorty/                 app-таргет: точка входу і склейка залежностей
│   ├── RickAndMortyApp.swift
│   └── ImagePipeline+Configuration.swift
├── Modules/                      локальний SPM-пакет з усім кодом
│   ├── Package.swift
│   ├── Sources/
│   └── Tests/
└── Screenshots/
```

Увесь код, окрім composition root, живе в локальному SPM-пакеті `Modules`, розділеному на сім бібліотечних таргетів.

### Таргети

`Models`: domain-структури `Character`, `CharactersPage`. Залежностей немає

`NetwokkClient`: інтерфейс мережі + реалізація на `URLSession`, DTO, `NetworkError`

`CharactersStorageRealm`: реалізація сховища. Єдиний таргет, що лінкує Realm

`CharactersStorage`: тільки інтерфейс сховища, без лінкування Realm

`CharactersList`: фіча: редʼюсер + в'юшки списку

`CharacterDetail`: фіча: редʼюсер + в'юшки деталей

`AppFeature`: навігація, `StackState`, кореневий `View`

## Стек

`swift-composable-architecture`:  редʼюсери, `StackState`, `TestStore`
`realm-swift`:  локальне сховище
`Nuke` / `NukeUI`:  завантаження і кешування зображень
`swift-dependencies` приходить разом із TCA транзитивно, тож окремої версійної політики не потрібно — резолвер тримає їх узгодженими. Він оголошений явно з іншої причини: SPM дозволяє посилатися на продукт лише з пакета, оголошеного у власному масиві `dependencies`, а `NetworkClient` і `CharactersStorage` потребують `import Dependencies` без усього TCA. `@DependencyClient` в інтерфейсних модулях


## Свідомі спрощення й відомі обмеження

**`deleteRealmIfMigrationNeeded: true`.** Несумісна схема скидає базу замість міграції. Тут допустимо, бо кеш відтворюється з мережі.

**Пагінація не продовжується з кешу.** Після запуску без мережі `currentPage` дорівнює 0 - мережа завжди запитує першу сторінку, а скрол нічого не вантажить до її відповіді.

**Екран деталей не робить запиту.** Цей екран показує `Character`, переданий списком. Модель повернута із запиту деталізації повернула б ті самі дані тільки екран був би ускладнений додатковою логікою.
